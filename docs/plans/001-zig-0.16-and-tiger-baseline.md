# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move sailor from Zig 0.15.2 to **0.16.0** — green `zig build test` on the full CI matrix — with
the kingdom `io: Io` convention on the public API, a machine-enforced `tidy` step, an assertion
baseline on the hot modules, and docs reconciled with reality. Ships as **v3.0.0**.

## Why now

sailor is a library with three consumers (zr, silica, zoltraak) and **zero dependencies**, so it
is `blocked_by: none` and can migrate now — while those three cannot start their own 0.16 work
until sailor is tagged. The probe counts 368 errors on `zig test src/sailor.zig`, dominated by
`std.io` → `std.Io` (155) and the `ArrayList` literal fixup (115), and that surface grows with
every widget added. The Tiger Style baseline rides along because the same files are already open:
9 asserts in 150k LOC, 28 `catch unreachable` against the repo's own rule, no automated guard.

## Scope

All items are `blocked_by: none`; order follows `citadel/core/rules/zig-0.16.md`. A wave outgrowing
one unattended cycle splits by module along `term → color → arg → repl → progress → fmt → tui`.

## Risks

- **A green `zig build test` has 3× failed to prove every widget's tests compiled** (orphaned-
  from-analysis-graph bugs) — gate each wave on the `zig test src/sailor.zig` count too, and note
  368 undercounts breakage (each unit stops at its first error), so re-probe after every wave.
- **`io: Io` is a hard break for three consumers** — no consumer bumps its hash until v3.0.0 is
  tagged, and the `docs/API.md` before/after lands first.
- **Concurrent heavy Zig builds have panicked this host** — check `pgrep -f "zig build"` first,
  and keep cross-compile and benchmarks CI-only outside STABILIZATION cycles.
- **Swallowed `error.Canceled` leaks resources**, and 28 `catch unreachable` already exist, so the
  `tidy` ban list lands before the Io waves, not after.

## Version impact

**MAJOR → v3.0.0.** `std.Io` changes public signatures across the CLI layer and the event loop,
and `.minimum_zig_version` forces every consumer onto a new toolchain — per
`citadel/protocol/VERSIONING.md` that is MAJOR for a library with consumers (zr, silica,
zoltraak). `build.zig.zon` is `2.99.0`, newest tag `v2.99.0`, so `3.0.0` is next: no skip.
